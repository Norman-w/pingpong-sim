状态：用于修复版 `pingpong-sim` 的浏览器录屏和成片交接。录屏是外部窗口采集，网页本身不导出 MP4；最终媒体放在仓库外的 `/Users/norman/Movies/pingpong-sim/spin-reversal/`。

## 这次重排解决什么

- 录屏时钟固定为显示时间的四分之一，Rapier 仍以 240 Hz 固定步长推进；30 fps 每帧约两个物理步，60 fps 每帧约一个物理步。
- 长帧不再一次性补偿最多 100 ms。录屏遇到浏览器卡顿时保持上一画面，避免球瞬移和“丢帧感”。
- 等 STL 和 Rapier 都完成后才发射第一轮；两球各完成两次真实落台并保留短暂上升段后才退场，空场后才进入下一轮。
- 相机只有一段匀速推进：先给全台面建立镜头，再推进到网和落点，随后保持；不绕球、不反向、不变焦、不用速度曲线炫技。
- 录屏隐藏交互式接球标记；碰撞提示只在实测台面接触位置短暂扩散，属于注释，不替代球和轨迹。
- 球保持 40 mm 直径并直接跟随 Rapier 刚体四元数；彩色分区随真实三维自转，不能用屏幕箭头冒充旋转。

## 录制操作

1. 启动 `npm run dev -- --host 0.0.0.0 --port 5173`，用 1920×1080 Chrome 窗口打开 `?recording=spin-reversal&recordingFps=60&mode=standard`、`critical`、`reversal`。
2. 等标题、STL 台面、网、指标卡全部出现后再开始外部窗口录制；每个条件录 30 秒、60 fps，文件保存为 `raw/v27/standard-60s.mov`、`critical-60s.mov`、`reversal-60s.mov`。
3. 录制期间不点网页暂停、不按 Space、不拖动鼠标到画面中央；录屏模式已经禁用 OrbitControls。
4. 片头、标准、临界和过零段按旁白时间轴从三条已验证原片抽取；机制和结论段允许重复使用过零片的稳定周期，但要用数据字幕明确这是解释镜头，不是新的物理试验。当前导出的实际规格与抽帧证据见 [`v27-media-manifest.md`](v27-media-manifest.md)。
5. 竖版不是横版缩小加黑边：以球、第二跳和指标卡为中心裁切，标题放上方、字幕放下方；若画面会裁掉网或落点，宁可保留横版母版，不强行输出竖版。

## 科学口径

一个球可以在不同阶段先是下旋、后来接近不转，甚至在特定条件下变成上旋，但不是所有下旋都会反转。是否过零取决于台面碰撞时的切向摩擦、入射速度和角度、初始旋转，以及球和台面的有效状态。空气阻力主要使旋转衰减；重力影响落台速度和法向冲量，但不直接把下旋变成上旋。RPM 和有效摩擦参数都必须标成仿真计算/参考模型值。
